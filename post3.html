企业级中后台权限管理系统

RBAC 权限模型 + 动态路由 + 按钮级权限

发布于 杨林 于 2026-10-20

几乎每个中后台系统都离不开「谁能看到什么、谁能做什么」。本文复盘我做的一套通用权限底座，前端 Vue3，后端 Spring Boot，核心是 RBAC 权限模型。

RBAC 权限模型

RBAC（基于角色的访问控制）的思路是：权限挂在角色上，用户绑定角色。用户 → 角色 → 菜单/按钮权限，三层关系清晰好维护。新增一个岗位，配好角色即可，不用逐个给用户配权限。

动态路由

不同角色登录后看到的菜单应该不一样。后端登录接口返回当前用户的权限菜单树，前端据此动态生成路由，而不是把路由写死：

// 根据后端返回的权限菜单动态生成路由
function buildRoutes(menus) {
  return menus.map(m => ({
    path: m.path,
    component: loadView(m.component),
    children: m.children ? buildRoutes(m.children) : []
  }));
}

按钮级权限

光控制菜单还不够，同一个页面里「删除」「审核」这类按钮也要按权限显隐。前端用 v-permission 指令按权限标识控制按钮，后端接口再做一次校验，双保险——前端隐藏只是体验，后端拦截才是安全。

JWT 无状态认证

登录成功后签发 JWT，后续请求带上 token，服务端无状态校验，配合刷新令牌实现免打扰续期，天然适配分布式部署。

数据权限

进阶一点，还需要控制「看哪部分数据」。比如部门主管只能看到本部门数据。我通过给查询接口注入数据范围条件来实现按部门、按本人的数据隔离。

权限系统的难点不在技术，而在模型设计得够不够灵活。把 RBAC、动态路由、按钮级权限、数据权限这四件事做扎实，基本就能覆盖绝大多数中后台场景。
